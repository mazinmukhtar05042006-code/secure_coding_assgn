Secure Coding Principles

Compact reference cards connecting theoretical secure coding principles to concrete implementations across this lab.

🛡️ Least Privilege
Meaning: Grant only the minimum necessary permissions required to complete a task.
In This Lab: Temporary files use 0600 restrictive permissions; Subprocesses run without root/admin shells.
🧱 Defense in Depth
Meaning: Layer multiple independent security controls to prevent single-point failures.
In This Lab: Input allowlists + structured subprocess APIs + HTTP security headers (CSP, X-Frame).
⚙️ Secure by Default
Meaning: The default system configuration must be the safest operational state.
In This Lab: Subprocess defaults to shell=False; File reading is sandboxed by default.
🛑 Fail Securely
Meaning: When errors occur, the system transitions to a secure state that denies unauthorized access.
In This Lab: Exceptions return generic user error messages while keeping stack traces internal.
🔍 Complete Mediation
Meaning: Every single access to protected resources must be checked on every invocation.
In This Lab: Canonical path resolution (Path.resolve()) is verified on every file read.
🎯 Minimize Attack Surface
Meaning: Eliminate unnecessary code paths, dependencies, open ports, and privileges.
In This Lab: Unnecessary external packages removed; commands run without spawning interactive shells.
🔐 Secure Data Handling
Meaning: Protect sensitive information at rest, in transit, and during processing.
In This Lab: Passwords hashed with salted PBKDF2; plaintext passwords never printed in logs or UI.
♻️ Secure Recovery
Meaning: Ensure failures and aborts restore safe invariants and clean up sensitive resources.
In This Lab: Python context managers (with blocks) ensure temp files are unlinked and destroyed on error.
👥 Separation of Duties
Meaning: Divide critical tasks across distinct mechanisms so no single component possesses unchecked authority.
In This Lab: Modular separation between routing, input validation, and security execution logic.
📖 Open Design
Meaning: Security must not depend on obscurity; cryptographic mechanisms must remain secure even if source is public.
In This Lab: Use of public, standardized algorithms (PBKDF2/scrypt) rather than custom obfuscation.
🧩 Economy of Mechanism
Meaning: Keep security designs as simple and small as possible to minimize flaws and ease verification.
In This Lab: Simple, focused validation helper functions without convoluted logic or bloated dependencies.
