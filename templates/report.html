1. Executive Summary

This report documents the security audit and engineering remediation performed on the six core vulnerabilities identified in the Secure Coding Assignment 1 case study. Each vulnerability was systematically evaluated, demonstrated under isolated conditions, and remediated using standard Python secure-coding practices guided by Modules 1 and 2. All fixes were validated through automated unit and integration test suites.

3. Implementation Priority Order & Justification

Implementation priority is based on the combination of likelihood and potential impact. Vulnerabilities with the greatest potential to compromise confidentiality, integrity, or availability and/or enable direct remote compromise are addressed earlier.

Priority 1 — OS Command Injection (Risk: CRITICAL): Addressed first because raw input directly reaching a shell interpreter allows complete host takeover, remote code execution, and data destruction. Mitigated via subprocess.run(shell=False) and strict allowlists.

Priority 2 — Plaintext Password Storage (Risk: CRITICAL): Addressed second because any database or backup exposure directly compromises all user accounts. Mitigated via salted PBKDF2/scrypt key derivation and constant-time verification.

Priority 3 — File Path Traversal (Risk: HIGH): Addressed third because attackers can read backend configuration, secrets, and code outside authorized document roots. Mitigated via pathlib.Path.resolve() and is_relative_to(base) boundary enforcement.

Priority 4 — Unmanaged External Dependencies (Risk: HIGH): Addressed fourth because applications inherit known CVEs from third-party supply chains. Mitigated via minimal manifests and automated SCA scanning (pip-audit).

Priority 5 — Predictable Temporary Files (Risk: MEDIUM): Addressed fifth because exploitation requires local access or specific race conditions. Mitigated via tempfile.NamedTemporaryFile with automatic disposal.

Priority 6 — Improper Exception Handling (Risk: MEDIUM): Addressed sixth because stack traces assist reconnaissance rather than granting immediate execution. Mitigated via typed exception handlers and sanitized user error messages.

4. Core Secure Coding Principles Applied
  • Least Privilege: Operations run with minimal permissions without invoking administrative shell interpreters.
  • Defense in Depth: Dual-layer protection using server-side allowlists before calling structured APIs.
  • Secure by Default: Safe default configurations, strict sandbox bounds, and automated security headers.
  • Fail Securely: Runtime exceptions fail safely without exposing internal implementation details or stack traces to end users.
  • Complete Mediation: Every file access request is canonicalized and validated on every single invocation.
  • Minimize Attack Surface: Reduced external dependencies, isolated sandbox directories, and no unnecessary command interfaces.
  • Secure Data Handling: Passwords hashed with high-work-factor algorithms; zero cleartext credential storage.
  • Secure Recovery: Context managers (with blocks) ensure all opened resources and temp files are destroyed even upon unexpected aborts.
5. Conclusion

All six weaknesses from the assignment case study have been systematically mitigated through defensive engineering controls. The application provides an interactive, safe demonstration of vulnerable and secure behaviors, accompanied by full automated test verification.
