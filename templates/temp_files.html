Predictable Temporary Files

Static or predictable temporary filenames allow symlink hijacking and race conditions; secure code uses tempfile.NamedTemporaryFile.

🛡️ SECTION C: Cryptographic Tempfile tempfile.NamedTemporaryFile 
# SECURE IMPLEMENTATION
import tempfile
with tempfile.NamedTemporaryFile(
    mode="w+", prefix="sec_report_", delete=True
) as tmp:
    tmp.write(report_data)
    # Automatically deleted upon exit

⚠️ SECTION B: What Went Wrong?
  • Predictable Path: A local attacker can predict shared_temp_report.txt and pre-create a malicious symlink.
  • No Atomic Creation: The application overwrote existing files without exclusive file creation flags.
  • Lingering Files: Temporary data was left on the disk indefinitely without guaranteed disposal.

🎯 SECTION E: Secure Coding Principle

Least Privilege & Minimize Attack Surface: Temporary files are created with restrictive permissions accessible solely to the executing process, and their attack surface is minimized by eliminating static filenames and enforcing immediate cleanup.

Why does this matter in real systems?

In multi-user or containerized shared host environments, predictable temp files (CWE-377) allow local privilege escalation and arbitrary file overwriting by tricking privileged background daemons into writing through symlinks.
